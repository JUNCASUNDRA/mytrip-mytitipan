# Framework Standards

## Repository Ownership Matrix
Defines which agent has `Write` access to specific directories. `Read` access is generally repository-wide for context.

| Directory | Owner (Write) | Contributor (Read) |
|-----------|---------------|-------------------|
| `docs/01-business/` | BAA | PMA, Human |
| `docs/02-product/` | PMA, TPA | BAA, SAA, DAA, DA |
| `docs/03-design/` | Human (UI Designer) | PMA, DA |
| `docs/04-technical/` | SAA, DAA | PMA, DA, RA |
| `docs/05-testing/` | RA | DA, Human |
| `apps/` | DA | RA, Human |
| `packages/` | DA | RA, Human |
| `infra/` | SAA | DA, Human |

## Artifact Naming Convention
All documents generated by agents must follow this pattern:
`[TYPE]-[ID]-[SLUG].md`

Examples:
- `BUS-001-executive-summary.md`
- `PRD-102-user-persona-traveler.md`
- `ARCH-201-system-architecture.md`
- `TASK-301-escrow-api-implementation.md`

## Versioning Strategy
1. **Document Versioning**: Every markdown file should include a metadata header with a version number (e.g., `v1.0.0`).
2. **Agent Versioning**: Agents must log their own version/model ID in the metadata of the files they create.
3. **Major/Minor Updates**:
    - **Patch (0.0.1)**: Typo fixes, minor clarifications.
    - **Minor (0.1.0)**: New user story, updated API endpoint.
    - **Major (1.0.0)**: New business module, architectural pivot.

## Metadata Header Template
Every agent-generated file MUST start with:
```markdown
---
agent: [Agent Name]
version: [Artifact Version]
date: [YYYY-MM-DD]
status: [Draft|Review|Approved]
predecessor: [Link to Source Artifact]
---
```
